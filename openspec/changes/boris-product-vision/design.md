# Design

## Context

Мотивация описана в `proposal.md`, требования в `specs/`. В этом репозитории кода пока нет. Есть первая версия в `~/Documents/sova` (дальше sova): около 13,5 тысячи строк Swift и 331 тест, все проходят. Она не продолжается, потому что её главная сущность это запуск workflow, и это не исправить без смены модели. Но в ней проверено поведение настоящего Claude Code, и её части переносятся (решение 2). Среда разработки: macOS 26.6, Xcode 27.1, Swift 6.4.

Источники данных проверены по документации, по файлам на машине пользователя и по проверкам в sova:

| Что нужно | Источник | Статус |
|---|---|---|
| Сессии и состояния | `~/.claude/sessions/<pid>.json`: `pid`, `procStart`, `cwd`, `entrypoint`, `status`, `waitingFor` | Внутренний формат |
| Действия | `tool_use` и `tool_result` в транскриптах `~/.claude/projects/**/*.jsonl` | Внутренний формат |
| Дерево агентов | `subagents/**/*.meta.json`: `parentAgentId`, `spawnDepth`, `agentType`, `toolUseId` | Внутренний формат |

| Токены | `message.usage` в транскриптах, считается по `message.id` | Внутренний формат |

Агент workflow, которому написали после конца запуска, пишет второй файл с тем же `id` рядом с агентами сессии (9 таких на 2045 файлов): записи в двух файлах почти не повторяются, это один агент | Внутренний формат |

| Лимиты и доплаты | `cachedUsageUtilization` в `~/.claude.json` | Внутренний формат |

| Ускорение и ответы | Хуки: `SessionStart`, `SessionEnd`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `SubagentStart`, `SubagentStop`, `Stop`, `StopFailure`, `Notification`, `PermissionRequest` | Документировано |

Среда определяется по полю `entrypoint`: `cli`, `claude-vscode`, `claude-desktop`, `local-agent` для Cowork, `sdk-*` для программ.

**Что уже проверено в sova на Claude Code 2.1.312:**

- Статус-строка с лимитами в расширении VS Code не работает.
- Хуки срабатывают внутри workflow с `agent_type: workflow-subagent`, но итога запуска в них нет.
- В терминале диалог разрешения виден сразу, пока хук ждёт. Ответ хука закрывает его в любой момент. Если хук молчит, диалог остаётся, а через 6 секунд приходит `Notification`.
- При `SIGKILL` хуков нет, а файл сессии остаётся. При `SIGTERM` приходит `SessionEnd`. Оба случая видны по файлам.
- Простая сумма выхода по транскрипту завышена в среднем в 2,6 раза из-за дублей.
- Из 102 запусков у 11 со статусом `completed` упали все агенты. Из 646 потерянных агентов 606 упали из-за лимита.
- На 300 транскриптах все 5849 вызовов инструментов получили результат, так что незакрытый вызов значит, что он идёт или агент умер.

**Что не проверено нигде:** пишет ли расширение VS Code `waitingFor` и срабатывает ли там `PermissionRequest` (в sova задачи 1.1 и 9.1 остались открытыми). Здесь это проверяется в задаче 8.1.

Замеры логов пользователя: 2263 файла, 2,8 ГБ, самый старый лог 57 дней. Простой проход по токенам занял 5,8 секунды скриптом на Python. За последние 7 дней изменилось 380 файлов на 1,1 ГБ. По умолчанию Claude хранит логи 30 дней (`cleanupPeriodDays`), а логи Desktop и Cowork без ограничения срока (`desktopSessionCleanupPeriodDays`).

## Goals / Non-Goals

**Goals:**

- Простая архитектура: один процесс приложения и маленький посредник для хуков.
- Приложение работает сразу после установки и ничего не меняет у Claude без согласия.
- Без базы данных, сервера и веб-части. Всё недоступное честно показывается как «нет данных».
- Знание внутренних форматов Claude собрано в одном модуле, чтобы при их смене правился только он.

**Non-Goals:**

- Универсальная платформа плагинов: для других агентов достаточно нового адаптера источника.
- Хранение истории дольше, чем её хранит Claude.
- Копирование текста переписки в данные Boris.
- Продолжение sova как проекта.

## Decisions

### 1. Нативное приложение на Swift

Swift 6 в строгом режиме, SwiftUI для экранов, AppKit для трея и панели чёлки, macOS 14 и новее, без внешних зависимостей, кроме средства автообновления.

- **Почему:** приложение должно быть лёгким, трей и чёлка всё равно требуют нативного кода, а после отказа от графа веб-часть не нужна. Готовый код sova тоже на Swift.
- **Альтернативы:** Tauri с React (чёлку всё равно дописывать нативно) и Electron (тяжёлый).

Сборка через Swift Package Manager и скрипты, Xcode-проект не нужен. Цели: `BorisCore` (модель и логика, покрывается тестами), `BorisData` (всё знание форматов Claude), `BorisCharacter` (морж), `Boris` (приложение), `boris-hook` (посредник), `boris-sheet` (контрольный лист моржа).

### 2. Перенос из первой версии

Не продолжаем sova и не пишем всё с нуля: новая модель и интерфейс плюс перенос проверенных частей.

| Что | Откуда в sova | Как |
|---|---|---|
| Чтение файлов Claude | `Sources/BorisData/` | Перенести; `RunScanner` разобрать под новую модель |
| Статусы и причины сбоев | `BorisCore/Status`, `BorisCore/Failure` | Перенести как логику узла workflow |
| Хуки | `boris-hook`, `Boris/Hooks`, `BorisCore/Hooks`, `BorisData/HookInstaller.swift` | Перенести, отвязать от запусков |
| Значок и система | `Boris/StatusBar`, `Boris/System`, `Boris/App/LaunchCoordinator.swift`, `Resources/app.boris.Boris.agent.plist` | Перенести |
| Морж | `BorisCharacter`, `BorisCore/Mood`, `BorisCore/Wardrobe`, `BorisCore/Play`, `Boris/Menu/Stage.swift`, `design/walrus`, `design/tools/walrus` | Перенести, исправить наряд со спины (решение 12) |
| Звуки | `Resources/Sounds`, `design/tools/voice.py`, `Boris/System/Voice.swift` | Перенести, `hoot` переименовать |
| Живая лента | `Boris/Menu/LiveActivityView.swift`, `Boris/Live/LiveWindow.swift`, `BorisCore/Activity` | Основа страницы сессии и «Активности» |
| Простые слова | `BorisCore/Menu/SimplePresentation.swift` | Основа справочника фраз |
| Уведомления | `Boris/Channels/BannerChannel.swift`, `BorisCore/Events` | Перенести |
| Проверки | `Tests/`, `scripts/make-fixtures.py`, `e2e.py`, `measure.py`, `check-strings.py`, `build-app.sh`, `install.sh` | Перенести и адаптировать |
| Строки | `Resources/Localizable.xcstrings`, `design/translations` | Брать только нужное |

**Делаем заново:** модель «проект → сессия → дерево агентов», чёлку, мини-окно, главное окно, страницы «Расход», «Потери» и «Запросы», Telegram, настройки источников, Cowork как полноценный источник, ответы на вопросы и планы.

**Выбрасываем:** `LegacyMigration`, остатки имени Sova, представление одиночного агента как запуска с префиксом `agent-`, выпадающий список как главный экран, статистику во вкладке настроек.

Sova благодарит Claude Code Monitor (MIT) за идеи: благодарность остаётся в титрах, а дословно перенесённые фрагменты идут с уведомлением о лицензии.

### 3. Файлы как основа, хуки как надстройка

Сессии, агенты, статусы и действия определяются по файлам Claude и работают без хуков с задержкой до 3 секунд. Хуки только помечают данные для немедленного чтения, добавляют то, чего нет в файлах (текущий инструмент, причина конца сессии), и открывают запрос на ответ.

- **Почему:** убитый процесс не вызовет хук, закрытый Boris теряет события навсегда, а итога workflow в хуках нет. Файлы к тому же работают там, где хуки запрещены компанией, и, вероятно, в Cowork.
- **Альтернатива:** основа на хуках, как у конкурентов и в первом варианте этого документа. Такой режим не поймает тихую смерть запуска.
- **Цена:** файлы внутренние и могут меняться, поэтому формат знает только `BorisData`, а смена формата видна в диагностике.

### 4. Модель: проект, сессия, дерево агентов

Главная сущность это работа, а не запуск. Проект содержит сессии, сессия содержит дерево узлов. Узел имеет тип (главный агент, субагент, форк, workflow, агент workflow) и родителя, глубина не ограничена: по документации субагент может запускать субагентов, по умолчанию до трёх уровней, а workflow запускает до 1000 агентов. В логах пользователя 2129 субагентов: 2117 на первом уровне и 12 на втором.

Источник приводит данные к этой модели, экраны знают только её. Пока есть адаптер Claude Code и адаптер Cowork. Coucou решает это похожим образом, сопоставляя события других агентов со своими каноническими.

Именно здесь sova свернула не туда: `WorldSnapshot` состоит из сессий и запусков, агенты живут только внутри запусков. Поэтому шапка меню писала «Nothing is running», пока сессия была занята.

### 5. Посредник для хуков

Хуки вызывают скомпилированный `boris-hook`. Он читает JSON, оставляет разрешённые поля и передаёт их через Unix-сокет `~/Library/Application Support/Boris/hook.sock` с правами 0600. Если сокета нет, сразу завершается с кодом 0.

- **Запись хука:** команда обёрнута в `test -x`, поэтому после удаления Boris она ничего не делает. Все события, кроме запросов, идут с `async: true`.
- **Почему не HTTP-хуки:** порт может занять другой процесс и ответить `allow`. В старых версиях Claude Code недоступный сервер к тому же приводил к отказу в разрешении.

### 6. Чтение файлов без нагрузки

FSEvents только помечает изменения: подписка на каталог с задержкой 0,5 секунды, проход не чаще раза в 2 секунды и только по помеченному. Журналы читаются с сохранённой позиции, транскрипты с конца: 64 КБ, при необходимости до 1 МБ. Живая лента читается только пока открыта: последние 4 МБ и дальше только дописанное. Полный проход для статистики идёт в фоне с низким приоритетом.

### 7. Без базы данных

Статистика строится чтением логов. Служебный файл с позициями и суммами служит только кэшем и строится заново, если его удалить.

- **Почему:** полный проход занимает секунды, а база добавила бы сложность без пользы.
- **Цена:** статистика доступна, пока Claude хранит логи. Пользователь это принял.
- **Альтернатива:** SQLite, как у MacPet. Её можно добавить позже, не меняя модель.

### 8. Точный подсчёт токенов

Числа два, и цена у них разная. Контекст берётся из последней записи и дёшев, он нужен для строки агента. Точный расход считается по `message.id` без дублей и требует полного чтения файла, он нужен для расхода и статистики.

### 9. Честные статусы и причины

Статус workflow считается чистой функцией в `BorisCore` по итоговому файлу, журналу и живости процесса: идёт, молчит (нет записей дольше 12 минут, порог настраивается), завершён, завершён с ошибками, упали все агенты, упал, остановлен, прерван. Источник истины в конце запуска это итоговый файл, а журнал только во время работы. Эталон для тестов: гистограмма по реальным запускам из фикстур sova.

Живость процесса проверяется по времени старта через `sysctl`, чтобы повторно использованный номер процесса не выглядел живой сессией.

Причина падения определяется по последней записи транскрипта: лимит, сеть, сон Mac, зависание, ошибка API, ошибка скрипта, неизвестно. Неизвестные случаи сохраняют исходный текст.

### 10. Ответы на запросы через блокирующий хук

На запросе `boris-hook` держит соединение с приложением и возвращает решение Claude:

| Запрос | Как отвечаем |
|---|---|
| Разрешение | `PermissionRequest`: `behavior` allow или deny, при отказе `message` |
| Вопрос | `AskUserQuestion`: разрешение плюс `updatedInput` с исходными `questions` и `answers` |
| План | `ExitPlanMode`: хук получает текст плана в `plan`, ответ allow или deny с `message` |

- **Безопасность:** ответ можно отправить только по соединению этого запроса, поэтому решение не попадёт в чужой запрос. `updatedPermissions` не используется: правила «всегда» настраиваются в самом Claude.
- **Запасной путь:** если приложение недоступно или ответа нет, посредник завершается без решения, и запрос остаётся в обычном интерфейсе Claude. Вопросы задаёт только главный агент: `AskUserQuestion` недоступен субагентам.
- **Время ожидания:** по умолчанию 2 минуты, настраивается. В терминале диалог виден, пока хук ждёт, поэтому ожидание не мешает ответить там. В sova было 30 секунд, этого мало, если человек отошёл. Если в VS Code диалог окажется скрыт на время ожидания, значение по умолчанию снижается до 30 секунд (задача 8.1).
- **Горячие клавиши:** Carbon `RegisterEventHotKey` не требует разрешений и регистрируется только пока видна карточка. Enter и кнопки в уведомлении ничего не разрешают: главный риск здесь случайное разрешение опасной команды.

### 11. Лимиты и доплаты из кэша Claude Code

Boris читает `cachedUsageUtilization` из `~/.claude.json` и оставляет только разрешённые поля: окна `five_hour`, `seven_day`, `seven_day_opus`, `seven_day_sonnet`, окна по моделям из `limits[]` и реальные доплаты из `extra_usage` (`is_enabled`, `used_credits`, `monthly_limit`, `decimal_places`, `currency`). `accountUuid` отбрасывается. Структура проверена на машине пользователя: окно `five_hour` пустое, что совпадает с планом Ultra, а `extra_usage` на месте.

Записи с кодовыми именами игнорируются: на проверке в sova запись с лимитом 250 $ оказалась не расходами сверх подписки, хотя выглядела похоже. Определять тип аккаунта отдельно не нужно: Boris показывает то, что нашёл, а для остального «нет данных».

**Обновление:** Claude Code пишет кэш только когда сам обращается к серверу, например по `/usage`. Поэтому Boris раз в 15 минут (настраивается и выключается) и по кнопке запускает Claude Code в псевдотерминале, из своей пустой папки, в чистом окружении и с `--setting-sources local`, и вызывает `/usage`. Вывод не сохраняется, а сессии из этой папки скрыты из списков.

- **Почему не статус-строка:** в расширении VS Code она не работает, а это основная среда пользователя. Кроме того, слот у неё один на все программы, и она требует правки настроек.
- **Почему не прямой запрос к серверу:** это потребовало бы токена из учётных данных и своего обращения в сеть.
- **Цена:** зависимость от интерфейса Claude Code. Если он изменится, данные перестанут обновляться, а подпись честно покажет их возраст.

### 12. Морж в коде, свои наборы файлами

Встроенный морж переносится как есть: `Pose` описывает глаза, брови, сигару, монокль, шляпу и наряд, `Renderer` рисует позу в трёх стилях (полный, упрощённый, одноцветный для трея 21×18 точек), а `Timeline` это чистая функция времени в позу. Скорость анимации растёт с числом агентов, с пределом.

Свои наборы это только файлы: описание, кадры по состояниям, реплики по языкам, звуки. Кода и скриптов в них нет, поэтому импорт безопасен. Оба варианта подключаются к приложению через один общий способ получить кадр по состоянию. Покупка наборов позже добавится поверх этого.

- **Почему не всё файлами:** шляпы умножили бы число кадров на все позы, а готовые анимации вроде падающей сигары были бы потеряны.
- **Цена:** два механизма рисования.

**Баг, который надо исправить при переносе.** `WalrusFull.drawFront` выбирает шляпу по `pose.headwear` (строки 74–80), а `drawBack` всегда рисует `bowler(pose.hat)` (строка 115) и всегда сигару (строка 104). Поэтому со спины пропадают шапка Деда Мороза, другие головные уборы и цветок, а рыба превращается в сигару. Тот же путь использует реакция «оборот» (`spin`), когда морж разворачивается спиной. Тест «Все реакции рисуются» проверяет реакции без наряда, поэтому баг не ловился. **Исправление:** общий код выбора шляпы и того, что во рту, для обеих сторон, и тест на все сочетания нарядов и реакций.

### 13. Поверхности и защита значка

- **Трей:** `NSStatusItem` и шаблонная картинка, система сама красит её под тему. Красная метка тревоги это отдельный слой. `MenuBarExtra` не подходит: его нельзя открыть из кода.
- **Значок за чёлкой:** новый значок появляется слева от остальных и на заполненной строке уходит за чёлку. При первом запуске Boris просит себе место через `NSStatusItem Preferred Position`, а положение значка проверяет по его рамке и `auxiliaryTopLeftArea`. Состояние окна не годится: заблокированный экран тоже считался бы скрытием.
- **Открытие без значка:** глобальная клавиша через Carbon, по умолчанию ⌥⌘O.
- **Чёлка и панель без чёлки:** одна неактивирующая панель `NSPanel`, положение зависит от наличия чёлки на экране.
- **Мини-окно:** `NSPopover` под треем.
- **Главное окно:** SwiftUI с боковой панелью.

### 14. Переход к сессии

| Среда | Способ | Что проверено на самом деле |
|---|---|---|
| VS Code | Сначала `vscode://file/<папка>`, потому что ссылка открывается в окне с фокусом, затем `vscode://anthropic.claude-code/open?session=<id>` | По коду расширения 2.1.318: `/open` принимает `session` и `prompt`, открытая вкладка получает `reveal()`, иначе создаётся новая. ### 15. Удалённые машины

Живые события идут через SSH-туннель к локальному сокету, как в Coucou. Логи остаются на удалённой машине, поэтому токены собирает маленький помощник на ней и передаёт только числа.

### 16. Cowork как источник только для чтения

Каждая папка `local-agent-mode-sessions/<организация>/<аккаунт>/agent/<id>/.claude` читается как отдельный корень с тем же форматом. Файлы `sessions` там называют процессы внутри виртуальной машины, поэтому живость определяется только по записи в файлы: сессия считается завершившейся после долгой тишины. Работа хуков в Cowork не подтверждена, поэтому на запросы Boris предлагает отвечать в Claude Desktop. Если хуки окажутся доступны, ответы добавятся без изменения модели.

### 17. Обычный чат Claude

Хуков там нет, переписка хранится на сервере. Как в Coucou, Boris через Accessibility проверяет наличие кнопки остановки ответа, текст чата не читается. Подход хрупкий и требует разрешения, а у самого Claude есть свои уведомления, поэтому чат выключен по умолчанию, включается в «Источниках» и делается последним (задача 13.3). Польза есть, когда уведомления Claude выключены.

### 18. Два режима как один экран с разной детализацией

Режим задаётся одной настройкой, которую читают экраны. Отдельных копий экранов нет. Понятные фразы берутся из локального справочника по типу действия, статуса и причины, с запасным вариантом для неизвестных случаев, и переводятся как обычные строки.

- **Почему не ИИ для описаний:** нужно работать без интернета, без расхода токенов и предсказуемо.
- **Почему простой режим по умолчанию:** он понятен и разработчику, и пользователю Cowork. В sova к этому пришли на практике: технические имена оказались непонятны без знания устройства Claude Code.

### 19. Источники как фильтр на входе

Источник это продукт плюс среда. Настройка проверяется при поступлении данных, поэтому выключенный источник не читается и не доходит до экранов, а итоги считаются без него.

- **Хуки:** они глобальные и не настраиваются по средам. `boris-hook` сразу завершается без решения, если источник выключен или ответы для него запрещены, поэтому Claude не ждёт.
- **Cursor и VS Code:** расширение может сообщать одинаковый `entrypoint`, поэтому при совпадении среда уточняется по дереву процессов (задача 15.1).
- **Снимки экрана:** окну с данными запрещённого источника выставляется `NSWindow.sharingType = .none`. Новые способы захвата экрана могут это обойти, и настройка об этом предупреждает.

### 20. Автозапуск, перезапуск и сон

`SMAppService.agent` с `RunAtLoad` и `KeepAlive: {SuccessfulExit: false}`: после падения launchd поднимает приложение (в sova проверено, за 1 секунду после `kill -9`), после выхода из меню нет. Постоянная подпись сохраняет автозапуск и разрешения между сборками.

«Не давать Mac уснуть» держит `PreventUserIdleSystemSleep` через IOKit, только пока идёт работа. По умолчанию выключено. Закрытая крышка всё равно усыпляет Mac. Сон остаётся отдельной причиной падений в потерях.

### 21. Telegram без сервера

Boris обращается к Telegram Bot API напрямую через бота пользователя. Токен хранится в Keychain. Своего сервера нет.

### 22. Распространение вне App Store

Песочница App Store не позволит читать файлы Claude и менять его настройки: у Coucou версия для App Store лишена многих функций. Распространяем подписанное приложение напрямую, обновления идут через Sparkle.

### 23. Языки

Строки хранятся в String Catalog, первые языки русский и английский. Черновые переводы из sova (8 языков) можно добавить позже.

### 24. Проверки

Логика проверяется модульными тестами без файлов и времени, чтение файлов на обезличенных реальных данных из `Tests/Fixtures`, сквозной сценарий на настоящих процессах через `e2e.py`, ресурсы через `measure.py`, строки через `check-strings.py`.

### 25. Нагрузка на Mac как расход, а не монитор

Блок отвечает на вопрос «во что работа Claude обходится Mac». Общая загрузка берётся через `host_statistics`, память через `host_statistics64`. По процессам используются `proc_listallpids` и `proc_pid_rusage`: для процессов своего пользователя разрешения не нужны. Конкретные вызовы уточняются при реализации, замеров на этом Mac ещё не было.

- **Группы:** процессы собираются по дереву родителей. В группу Claude входят процессы сессий из реестра со всеми потомками (серверы MCP, команды), и они вычитаются из редактора, иначе были бы учтены дважды. Cowork виден как процесс виртуальной машины, чат неотделим от Claude Desktop.
- **«Остальное»:** считается как общая загрузка минус названные группы. Поэтому сумма всегда сходится, а чужие системные процессы читать не нужно.
- **Процессор:** 100 % это все ядра, поэтому цифры отличаются от «Мониторинга системы», где каждое ядро считается за 100 %. На экране есть пояснение.
- **Диск:** доля занятого берётся из свойств тома, а размер логов Claude известен из их чтения. Разбивка по приложениям потребовала бы обхода всего диска, поэтому её нет.
- **Цена замера:** таймер работает только пока блок виден, а внешние команды вроде `ps` не запускаются.
- **Альтернатива:** полный монитор, как у MacPet. Он отвергнут: это дублирует «Мониторинг системы» и ведёт к расползанию продукта.

### 26. Раздел «О Boris» и поддержка автора

Раздел живёт в настройках и открывается из меню значка, а не из боковой панели: он нужен редко и не должен стоять в одном ряду с рабочими страницами. Так же было в sova, откуда переносятся титры и благодарность за Claude Code Monitor.

- **Кнопка кофе:** это обычная ссылка, которая открывается в браузере. Boris не обращается в сеть и не принимает платежи, поэтому принцип работы без интернета не страдает. Без заданной ссылки кнопки нет.
- **Автор и лицензия:** автор Игорь Богданов. Код под MIT, а морж, реплики и звуки защищены, все права сохранены, как у Coucou. Морж нарисован в коде, поэтому без явного исключения MIT распространился бы и на него: в `LICENSE` перечислены `Sources/BorisCharacter`, `design/walrus`, `design/tools/walrus`, `design/tools/voice.py`, `Resources/Sounds` и файлы реплик.
- **Тексты лицензий:** они лежат внутри приложения и читаются без сети. Сторонние лицензии, например Sparkle, собраны в одном файле.
- **Уведомление:** приложение использует имя Claude, поэтому в разделе указано, что Boris не связан с Anthropic.

### 27. Макет как эталон, а не код

Макет из Claude Design сохранён в `design/claude-design/` с номером версии холста. Это HTML, а приложение на SwiftUI, поэтому в приложение он не встраивается: из него берутся токены, тексты, размеры и состояния. Веб-часть убрана ещё вместе с графом.

- **Морж:** в макете заглушка, настоящий вставляется при сборке из готового кода.
- **Цвета бренда:** временные значения макета заменяются цветами моржа из кода: лента `B3313F`, золото `F4C542`, котелок `2F2E44`, шкура `A9704F`, усы `F7EAD3`. Контраст проверяется при переносе. Правило из макета сохраняется: бренд только рядом с моржом, в облачке и на странице «Морж», а в статусах и кнопках его нет, чтобы красный ленты не путался с тревогой.
- **Принято из макета:** клавиши ⌥⌘Y и ⌥⌘N, полоса фаз workflow, строка «Без проекта», столбцы «Где ответили» и «Ждал», «Не беспокоить до 17:21».
- **Порядок переноса:** экран за экраном вместе с данными, а не всё сразу: токены и базовые компоненты, страница сессии на настоящих данных, затем остальное.
- **Адаптивность и стабильность:** экраны макета фиксированного размера, поэтому проверяется само приложение. Режим снимков `BORIS_SNAPSHOT` из sova расширяется до автоматических снимков каждого экрана в обеих темах, обоих режимах и на двух языках, в минимальном и большом размере, с длинными строками и пустыми данными, на экранах с чёлкой и без. Снимки сравниваются с макетом и с прошлой версией.
- **Документация:** окно «Как устроен Boris» в макете есть, но текст лёгкой документации пишется позже вместе с пользователем. В этой версии окно не переносится.

## Risks / Trade-offs

- [В VS Code не подтверждена работа `PermissionRequest` и поведение диалога, пока хук ждёт, а это основная среда пользователя] → Проверяем первым делом в задаче 8.1. Если не работает, Boris показывает, что сессия ждёт ответа, и открывает её.
- [Внутренние форматы Claude могут измениться] → Всё знание в `BorisData`, неизвестные поля игнорируются, фикстуры фиксируют проверенную версию, диагностика сообщает о смене формата вместо пустого экрана.
- [Скрытый запуск Claude Code для `/usage` хрупкий] → Настройка его выключает, сбой не ломает остальное, подпись показывает возраст данных.
- [Статистика ограничена сроком хранения логов] → Решение принято, дата начала данных всегда показана.
- [Другая программа перезаписывает `settings.json`] → Следим за файлом, диагностика предлагает починку, подозрительный файл не перезаписываем.
- [Токены на скиллы и интернет нельзя измерить точно: расход считается на запрос, а не на инструмент] → Вызовы считаем точно, токены подписываем как оценку.
- [Частые хуки могут замедлять Claude] → Обычные события идут с `async: true`, задержка проверяется замером в группе 2 задач.
- [Случайное разрешение опасной команды] → Команда видна целиком, клавиши активны только при видимой карточке, Enter и уведомления ничего не разрешают, решения «всегда» нет.
- [Формат Cowork изучен на единственной старой сессии] → Перед реализацией адаптера разбираем свежую сессию (задача 13.1), недоступное показываем как «нет данных».
- [Два механизма рисования моржа] → Встроенный и наборы подключаются одним способом, экраны о различии не знают.
- [Перенос затянет за собой старую модель запусков] → Новая модель пишется первой, переносимый код адаптируется к ней, а не наоборот.
- [Память процессов не складывается точно из-за общей памяти, а цифры расходятся с «Мониторингом системы»] → Значения приблизительные, расхождение процессора поясняется на экране, а «Остальное» сводит сумму к общей нагрузке.
- [Расползание продукта, как в прошлых попытках] → Новые идеи идут в список «на потом» в `proposal.md`, крупные разделы делаются отдельными группами с проверкой в конце каждой.
- [Заимствование у конкурентов] → Код и графику не копируем: Clawd под AGPL-3.0, а имя, персонаж и звуки Coucou защищены. Морж и звуки Boris свои.

## Migration Plan

Старая версия сейчас работает как фоновый агент `app.boris.Boris.agent` из `~/Applications/Boris.app`. Обе копии одновременно не запускаем: у них общая папка данных и сокет.

1. Перед первым запуском новой версии старая останавливается вместе с пользователем (задача 1.5). Хуков от неё в `~/.claude/settings.json` нет, поэтому откатывать в настройках нечего.
2. Идентификатор приложения остаётся `app.boris.Boris`, чтобы система не спрашивала разрешения заново.
3. Настройки и статистика старой версии не переносятся. Статистика строится заново из логов.
4. Откат: остановить новую версию и снова запустить старую из папки `sova`. Хуки нового Boris убираются кнопкой «Отключить» и резервной копией настроек.

## Open Questions

- Какой сервис и какая ссылка для кнопки кофе. Пользователь отложил это решение. Пока ссылки нет, кнопка не показывается.
- Форма помощника для удалённой машины: скрипт или отдельная сборка под Linux. Выбирается в группе 12 задач.
- Есть ли сертификат Developer ID для нотаризации. На этом Mac есть Apple Development и Apple Distribution. Нужен к выпуску, на разработку не влияет.
- Откуда брать лимит расходов для корпоративного шлюза, раз статус-строка не используется. В кэше есть поле `spend`, смысл которого не проверен. Если не подойдёт, для шлюза показывается «нет данных».
- Что означает поле `fallback_credit` в логах. У пользователя оно пока всегда пустое. На требования не влияет, потому что доплаты берутся из `extra_usage`.
