# Spec Delta

## Purpose

Показывает, что происходит в работе Claude прямо сейчас: от проектов и сессий до отдельных агентов и их действий.

## ADDED Requirements

### Requirement: Иерархия работы
Boris SHALL организовывать данные как «проект → сессия → дерево агентов → действия».

#### Scenario: Сессия без проекта
- **WHEN** у сессии нет рабочей папки
- **THEN** она показана в строке «Без проекта»

#### Scenario: Переход вниз по иерархии
- **WHEN** пользователь открывает проект, затем сессию
- **THEN** он видит сессии проекта, затем дерево агентов и действия выбранной сессии

### Requirement: Живые сессии
Boris SHALL показывать идущие сессии со средой, проектом, состоянием и временем работы. Состояния: работает, ждёт вас, завершена, сбой, прервана.

#### Scenario: Сессия ждёт ответа
- **WHEN** Claude в сессии запросил разрешение
- **THEN** сессия переходит в состояние «ждёт вас»

#### Scenario: Занятая сессия без workflow
- **WHEN** сессия занята, а workflow не запущены
- **THEN** Boris показывает, что идёт работа, а не «ничего не идёт»

#### Scenario: Сессия завершила ход
- **WHEN** Claude закончил работу и ждёт нового запроса пользователя
- **THEN** сессия переходит в состояние «завершена»

### Requirement: Дерево агентов
Boris SHALL показывать дерево агентов сессии любой глубины обычным списком с отступами. Типы узлов: главный агент, субагент, форк, workflow и агент workflow.

#### Scenario: Субагент запускает субагента
- **WHEN** субагент запускает ещё одного субагента
- **THEN** новый агент появляется в дереве на уровень глубже своего родителя

#### Scenario: Состояние агента
- **WHEN** агент работает, ждёт ответа, завершился или упал
- **THEN** его строка в дереве показывает это состояние, текущее действие и токены

### Requirement: Workflow
Boris SHALL показывать workflow как отдельный узел с названием, состоянием, фазами, числом агентов и токенами.

#### Scenario: Ход по фазам
- **WHEN** workflow идёт
- **THEN** его строка показывает полосу фаз с готовыми, идущими и упавшими агентами

#### Scenario: Большой workflow
- **WHEN** в workflow работает много агентов
- **THEN** они свёрнуты по фазам со счётчиком, а по нажатию фаза раскрывается

### Requirement: Честные статусы workflow
Boris SHALL определять статус workflow по итогу, его агентам и живости процесса, а не только по итоговому полю Claude. Статусы: идёт, молчит, завершён, завершён с ошибками, упали все агенты, упал, остановлен, прерван.

#### Scenario: Завершён, но упали все агенты
- **WHEN** Claude записал итог `completed`, а все агенты упали
- **THEN** Boris показывает «упали все агенты», а не «завершён»

#### Scenario: Упала часть агентов
- **WHEN** Claude записал итог `completed`, а часть агентов упала
- **THEN** Boris показывает «завершён с ошибками» и число упавших

#### Scenario: Процесс умер без итога
- **WHEN** итога нет, а процесс Claude Code умер
- **THEN** Boris показывает «прерван»

#### Scenario: Долго нет записей
- **WHEN** итога нет, процесс жив, а записей нет дольше порога, по умолчанию 12 минут
- **THEN** Boris показывает «молчит»

### Requirement: Живая лента действий
Boris SHALL показывать действия агентов в реальном времени с типом: чтение, запись, команда, поиск в интернете, скилл, MCP, запуск агента.

#### Scenario: Агент читает файл
- **WHEN** агент читает файл
- **THEN** в ленте появляется запись с агентом, типом действия и именем файла

#### Scenario: Фильтр по типу
- **WHEN** пользователь выбирает в ленте фильтр «команды»
- **THEN** лента показывает только выполнение команд

### Requirement: Записи и прокрутка ленты
Лента SHALL показывать запрос человека, шаги агента со временем и длительностью, заметки Claude и признак «Думает…». Лента SHALL сама идти за последней записью, пока пользователь не прокрутит её вверх.

#### Scenario: Пользователь прокрутил вверх
- **WHEN** пользователь прокрутил ленту вверх и появились новые записи
- **THEN** лента остаётся на месте и показывает кнопку «К последнему»

#### Scenario: Упавший шаг
- **WHEN** шаг упал или ещё идёт
- **THEN** он раскрыт сразу, а успешные шаги раскрываются по нажатию

### Requirement: Правки файлов
Boris SHALL показывать при каждой правке имя файла и число добавленных и удалённых строк, а по нажатию полный текст изменений.

#### Scenario: Просмотр правки
- **WHEN** агент изменил файл и пользователь нажал на запись в ленте
- **THEN** Boris показывает удалённые и добавленные строки

### Requirement: Отметка worktree
Boris SHALL отмечать агентов и сессии, которые работают в отдельной копии проекта (worktree). Boris MUST NOT запускать задачи в worktree.

#### Scenario: Агент в отдельной копии
- **WHEN** агент работает в worktree
- **THEN** его строка в дереве отмечена как работа в отдельной копии с названием ветки

### Requirement: Переход к сессии
Boris SHALL открывать окно или вкладку сессии из любого места, где эта сессия показана. Если точный переход недоступен, Boris SHALL открыть приложение среды.

#### Scenario: Сессия в VS Code
- **WHEN** пользователь нажимает «Открыть» у сессии из VS Code
- **THEN** открывается VS Code с вкладкой этой сессии

#### Scenario: Сессия в терминале
- **WHEN** пользователь нажимает «Открыть» у сессии из терминала
- **THEN** на передний план выходит окно терминала с этой сессией

#### Scenario: Точный переход недоступен
- **WHEN** среда не позволяет открыть конкретную сессию
- **THEN** Boris открывает приложение этой среды

### Requirement: Прошлые сессии
Boris SHALL показывать список прошлых сессий с фильтрами по проекту и дате в пределах логов, которые хранит Claude. Поиск по тексту переписки MUST NOT входить в эту функцию.

#### Scenario: Открытие прошлой сессии
- **WHEN** пользователь выбирает прошлую сессию
- **THEN** Boris показывает её дерево агентов, расход и сбои

#### Scenario: Логи удалены
- **WHEN** Claude удалил логи старой сессии
- **THEN** эта сессия больше не показывается в списке
