# Spec Delta

## Purpose

Определяет, откуда Boris получает данные о работе Claude и как приводит их к единому виду, не мешая самому Claude.

## ADDED Requirements

### Requirement: Три продукта Claude
Boris SHALL понимать три продукта: Claude (обычный чат), Cowork и Claude Code. Для каждого он показывает столько данных, сколько этот продукт позволяет получить, и MUST явно отмечать, чего не хватает.

#### Scenario: Работа в трёх продуктах сразу
- **WHEN** одновременно идут чат Claude, сессия Cowork и сессия Claude Code
- **THEN** Boris показывает все три с указанием продукта

#### Scenario: Данных о продукте мало
- **WHEN** пользователь открывает обычный чат Claude, для которого известен только факт готовности ответа
- **THEN** Boris показывает этот факт и поясняет, что токены и действия чата недоступны

### Requirement: Сбор данных из сред Claude Code
Boris SHALL получать данные о работе Claude Code в терминале, в расширениях VS Code и Cursor и на вкладке Code в Claude Desktop.

#### Scenario: Сессия в VS Code
- **WHEN** пользователь запускает Claude Code в расширении VS Code
- **THEN** сессия появляется в Boris с указанием среды «VS Code»

#### Scenario: Сессия во вкладке Code
- **WHEN** пользователь запускает сессию на вкладке Code в Claude Desktop
- **THEN** сессия появляется в Boris с указанием среды «Claude Desktop»

### Requirement: Сессии Cowork
Boris SHALL показывать сессии Cowork со средой «Cowork»: папку или название задачи, состояние, модель, действия и токены, насколько их можно получить из файлов Claude Desktop.

#### Scenario: Идёт сессия Cowork
- **WHEN** на этом Mac идёт сессия Cowork
- **THEN** она появляется в Boris со средой «Cowork»

#### Scenario: Данные Cowork недоступны
- **WHEN** часть данных Cowork нельзя получить или разобрать
- **THEN** Boris показывает сессию и отмечает эти данные как «нет данных»

### Requirement: Файлы как основа
Boris SHALL определять сессии, агентов, статусы и действия по файлам Claude и работать сразу после установки, не меняя настроек Claude. Хуки MUST только ускорять обновление и давать ответы на запросы, а статусы MUST NOT зависеть от них.

#### Scenario: Хуки не подключены
- **WHEN** хуки не подключены и в Claude идёт работа
- **THEN** сессии, дерево агентов, лента и расход работают, а обновление приходит не позже чем через 3 секунды

#### Scenario: Хуки подключены
- **WHEN** хуки подключены и в Claude происходит событие
- **THEN** Boris показывает его сразу, а статус остаётся таким же, как без хуков

#### Scenario: Boris был закрыт
- **WHEN** работа шла, пока Boris был закрыт
- **THEN** после запуска он восстанавливает её состояние из файлов

### Requirement: Сессии без файла сессии
Boris SHALL показывать сессии, которые оставляют только логи: Cowork, программы на Agent SDK и Claude Code, запущенный внутри другого Claude. Такая сессия SHALL считаться завершившейся после долгого отсутствия записей.

#### Scenario: Программа на SDK
- **WHEN** программа на Agent SDK пишет лог сессии
- **THEN** Boris показывает её с указанием, что это программа

#### Scenario: Долгая тишина
- **WHEN** в логи такой сессии давно нет записей
- **THEN** Boris перестаёт считать её идущей

### Requirement: Среда как свойство сессии
Boris SHALL хранить среду как свойство сессии, а не как родителя проекта, потому что один проект может быть открыт в нескольких средах.

#### Scenario: Один проект в двух средах
- **WHEN** один и тот же проект открыт в VS Code и в терминале
- **THEN** Boris показывает один проект с двумя сессиями в разных средах

### Requirement: Обычный чат Claude Desktop
Boris SHALL показывать для обычного чата Claude Desktop факт готовности ответа. Функция требует разрешения Accessibility и MUST включаться только с согласия пользователя, а текст чата MUST NOT читаться.

#### Scenario: Ответ готов
- **WHEN** функция включена и обычный чат Claude Desktop закончил ответ, пока приложение Claude не на переднем плане
- **THEN** Boris сообщает, что ответ готов, без текста ответа

#### Scenario: Включение
- **WHEN** пользователь включает чат Claude в разделе «Источники»
- **THEN** Boris объясняет, зачем нужно разрешение Accessibility, и запрашивает его

#### Scenario: Функция не включена
- **WHEN** пользователь не дал согласия
- **THEN** Boris не обращается к окну Claude Desktop и показывает чат как не подключённый

### Requirement: Единая модель событий
Boris SHALL приводить данные любого источника к единой модели событий, чтобы экраны не зависели от источника. В этой версии поддерживается только Claude, но модель MUST допускать добавление других агентов без изменения экранов.

#### Scenario: Новый источник
- **GIVEN** новый источник приводит свои данные к единой модели
- **WHEN** от него поступает событие
- **THEN** событие показывается на тех же экранах, что и события Claude

### Requirement: Удалённые машины по SSH
Boris SHALL показывать сессии Claude на удалённых машинах, которые подключил пользователь, с указанием имени машины.

#### Scenario: Сессия на удалённой машине
- **WHEN** на подключённой удалённой машине идёт сессия Claude
- **THEN** Boris показывает её живые события и запросы с именем этой машины

#### Scenario: Потеря связи
- **WHEN** связь с удалённой машиной обрывается
- **THEN** Boris отмечает её сессии как «нет связи», а работа Claude на этой машине продолжается

### Requirement: Claude не зависит от Boris
Boris MUST NOT нарушать работу Claude. Если Boris не запущен или недоступен, Claude SHALL работать так же, как без него.

#### Scenario: Boris не запущен
- **WHEN** Claude работает, а Boris закрыт
- **THEN** Claude продолжает работу без ошибок и задержек и спрашивает разрешения в своём обычном интерфейсе

### Requirement: Восстановление при запуске
При запуске Boris SHALL находить уже идущие сессии и MUST отмечать сессии, процесс которых исчез без события завершения.

#### Scenario: Запуск во время работы Claude
- **WHEN** Boris запускается, пока идут сессии Claude
- **THEN** эти сессии сразу появляются в списке

#### Scenario: Процесс исчез
- **WHEN** процесс сессии завершился без события завершения, например после `kill -9`
- **THEN** Boris отмечает сессию как «прервана»

#### Scenario: Номер процесса занят другим
- **WHEN** номер процесса сессии теперь принадлежит другому процессу
- **THEN** Boris не считает сессию живой

### Requirement: Устойчивость к изменению форматов
Boris SHALL продолжать работу, если обновление Claude изменило формат данных: незнакомые поля игнорируются, а недоступные показатели отмечаются как «нет данных».

#### Scenario: Изменился формат логов
- **WHEN** после обновления Claude часть данных больше не удаётся разобрать
- **THEN** Boris не падает, показывает остальные данные и отмечает недоступные как «нет данных»
