# Как выпустить Boris

Одна команда собирает, подписывает, отправляет на нотаризацию и готовит обновление. Перед первым выпуском нужно один раз сделать три вещи: сертификат, пропуск для нотаризации и ключ обновлений. Без них команда остановится и скажет, чего не хватает.

## Один раз перед первым выпуском

Всё ниже делается на том Mac, с которого будут выпуски, и всё остаётся в его Keychain. Скрипты ничего не создают сами.

### 1. Сертификат Developer ID Application

Нужен платный аккаунт Apple Developer. Сертификаты Apple Development и Apple Distribution, которые уже есть на этом Mac, не подходят: первый только для разработки, второй для App Store.

1. Откройте Xcode → Settings → Accounts → выберите команду → Manage Certificates.
2. Нажмите «+» → Developer ID Application.
3. Проверьте в Терминале:

   ```
   security find-identity -v -p codesigning | grep "Developer ID Application"
   ```

   Должна появиться одна строка.

### 2. Пропуск для нотаризации

1. На [account.apple.com](https://account.apple.com) → Sign-In and Security → App-Specific Passwords создайте пароль с именем `boris-notary`.
2. Узнайте Team ID: он в скобках в той строке из шага 1.
3. Сохраните пропуск. Команда спросит пароль и положит его в Keychain:

   ```
   xcrun notarytool store-credentials boris-notary --apple-id ВАШ@EMAIL --team-id TEAMID
   ```

Другое имя пропуска можно задать через `BORIS_NOTARY_PROFILE`.

### 3. Ключ обновлений Sparkle

Этим ключом подписывается каждое обновление, а его открытая половина лежит в приложении. Установленные копии примут только то, что подписано этим ключом.

```
swift package resolve
.build/artifacts/sparkle/Sparkle/bin/generate_keys
```

Сразу сохраните копию закрытого ключа в надёжное место, не в репозиторий:

```
.build/artifacts/sparkle/Sparkle/bin/generate_keys -x ~/Desktop/boris-sparkle-key
```

**Если ключ потеряется, уже установленные копии больше никогда не обновятся сами:** людям придётся скачать новую версию вручную. Перенести ключ на другой Mac: `generate_keys -f файл`.

## Выпуск

Необязательно, но приятно: положите заметки о версии в `docs/release-notes/0.2.0.md`. Их покажет окно обновления. Без файла GitHub составит заметки по коммитам.

Закоммитьте всё, затем:

```
scripts/release.sh 0.2.0 --publish
```

Что происходит по порядку:

1. Проверка, что сертификат, пропуск и ключ на месте и в репозитории нет незакоммиченных изменений.
2. `check-strings.py`, `swift test`, `measure.py app`, `check-network.py`.
3. Сборка с версией `0.2.0` и номером сборки по числу коммитов: Sparkle сравнивает именно номер. В приложение записываются адрес ленты и открытый ключ.
4. Подпись изнутри наружу, с hardened runtime и меткой времени.
5. `check-bundle.sh --release` смотрит внутрь: лицензии, Sparkle, подпись, нет ли отладочных хуков и путей этого Mac.
6. Нотаризация в Apple, несколько минут. Если Apple откажет, скрипт напечатает причину.
7. Архив `build/release/archives/Boris-0.2.0.zip` и лента `appcast.xml` с подписью обновления.
8. Выпуск на GitHub: тег `v0.2.0`, архив и лента.

Без `--publish` всё то же, но шаг 8 только печатается: можно сначала посмотреть глазами.

Лента живёт по адресу, который не меняется: `https://github.com/bogdanov-igor/boris/releases/latest/download/appcast.xml`. GitHub отдаёт её из последнего выпуска, поэтому выпуск нельзя помечать как pre-release, если его должны получить все.

`scripts/release.sh 0.2.0 --dry-run` работает и без сертификата и ключа: собирает с настоящими настройками и hardened runtime, смотрит внутрь и останавливается. Такую сборку не запускают.

## Проверка обновления со старой версии на новую

Это последняя проверка задачи 16.1, и сделать её можно только с настоящим сертификатом и ключом.

1. Выпустите `0.2.0`: `scripts/release.sh 0.2.0 --publish`.
2. Скачайте архив с GitHub, распакуйте, перенесите Boris в «Программы» и запустите. Если стоит копия из `install.sh`, сначала закройте её и удалите.
3. Проверьте: Настройки → Общие показывает «Версия 0.2.0», кнопка «Проверить» отвечает «Последняя версия», а macOS не ругается на неизвестного разработчика.
4. Сделайте любой коммит и выпустите `0.2.1`: `scripts/release.sh 0.2.1 --publish`.
5. В Boris нажмите «Проверить». Строка скажет, что доступна версия 0.2.1, а над страницами главного окна появится плашка.
6. Нажмите «Обновить». Откроется окно Sparkle с заметками. Нажмите в нём установку. Boris закроется и откроется заново.
7. Проверьте:
   - в настройках «Версия 0.2.1»;
   - значок вернулся в строку меню;
   - «Запускать при входе» осталось включённым;
   - подключённые ответы работают: `boris-hook` лежит по тому же пути;
   - сессии Claude, шедшие во время обновления, продолжаются. Запрос, ждавший ответа, остаётся в самом Claude.
8. Выключите интернет и нажмите «Проверить»: строка спокойно скажет «Нет связи», окон и ошибок нет. Включите интернет: автоматическая проверка, если она тоже не прошла, повторится сама.

## Что уходит с Mac при проверке обновлений

Только один запрос `GET` к адресу ленты. В нём нет параметров, а из заголовков, кроме обычных для HTTP, только `User-Agent: Boris/0.2.0 Sparkle/2.10.1`. Профиль системы выключен, данных о проектах и сессиях нет. Это проверяет `scripts/check-network.py` на настоящем Sparkle и `OutgoingConnectionsTests` на каждом прогоне тестов.

Проверяют только выпущенные копии. Отладочная сборка и копия из `install.sh` не обращаются к ленте вообще: в них нет адреса и ключа, а в настройках написано, что такая копия обновления не проверяет.

## Как обновить сам Sparkle

1. В `Package.swift` поменяйте точную версию, затем `swift package update`.
2. В `THIRD_PARTY_LICENSES.txt` поменяйте версию и сверьте текст с `.build/artifacts/sparkle/Sparkle/LICENSE`.
3. Прогоните `swift test` и `scripts/check-network.py`, затем проверку обновления выше.
